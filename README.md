teams_config.csv
  This is the configuration file that says:
  which teams
  which years
  which genders
  to scrape in bulk.
  It is read by scripts like dump_recruiting_data.py
  essentially tells the dump scripts which teams which genders and which years should we scrape specifically
  (some dump scripts this is not necessary like getting single swimmer data)

collegeSwimmingTeams.csv
  master list of all college teams scraped from swimcloud
  generated by getteamlist.py which scrapes all of https://www.swimcloud.com/team/?page=X and saves the result
  powers functions like say give me all ACC teams give me all D1 teams give me ID numbers for UF search for any team by name.

dump scripts
  the small python scripts like dump_uf_roster these are purly to pull data and save it as CSV.
  They are meant to produce stable files and can be re-run.
  Then with those we can work in Python,R,SQL without having to return to the website too many times unless we need an update
  To get CSVs simply run in terminal
  python (whatever script ex: dump_recruits_2028.py)

Explanation of the new part HTML part JSON strategy for scraping
  Anywhere we can find a JSON endpoint in DevTools on the swimcloud site, we pivot the code to use that instead of parsing HTML.
  JSON is structured, more stable, and easier to analyze. HTML remains only where there’s no known API yet. The parts were we cannot find
  a JSON endpoint are still using HTML parsing.

  example: getRoster(team, gender, year, team_ID) [HTML strategy]
    this still parses the roster table HTML for the moment it builds a URL requests.get(url...) then uses beautiful soup to locate tables etc.
    then it converts everything into python.
  
  example: getTeamPerformance(team_id...) [JSON strategy]
    I could find a JSON endpoitn for this so the url is instead a JSON endpoint: https://www.swimcloud.com/api/performances/get_for_team/
    with query parameters like team_id, gender, event_course etc.
    so it uses that instead and returns a list of dicts containing all the data.
